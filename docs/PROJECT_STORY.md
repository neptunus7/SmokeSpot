# SmokeSpot 프로젝트 이야기

## 출발점

흡연자이면서도 길거리 흡연으로 주변 보행자가 불편을 겪는 문제를 의식했습니다. 흡연자에게 이용할 공간이 필요한 만큼, 비흡연자의 간접흡연 노출과 담배꽁초를 줄이는 조건도 중요하다고 생각했습니다. **'시설을 더 둘까?'보다 '어디에 두어야 두 집단의 불편을 줄일 수 있을까?'** 에서 시작한 개인 프로젝트입니다.

## 처음 계획과 달라진 것

초기에는 지도 반경 500m에서 후보지를 자동으로 추천하는 기능을 상상했습니다. 기능을 만들어보니 실제 학교·공원·보도 경계를 구분해야 하고, 같은 '인구'라는 자료도 주거인구와 생활인구의 단위와 의미가 다르며, 공개되지 않은 격자값도 존재한다는 것을 알게 됐습니다.

M1(상가 인근 흡연 공간)과 M2(주거지 옆 공터)를 직접 살펴보며 **현장에 사람이 사용하는 공간이 있다고 해서 수치상 평가가 가능한 것도 아니고, 수치가 좋아도 곧바로 설치할 수 있는 것도 아니다**라는 점을 확인했습니다. M2에서는 주거인구 충족률 때문에 80% 기준에서 점수를 계산할 수 없었고, 50% 기준 실험을 통해 분석의 취약성을 드러냈습니다.

그래서 섹터와 선택 영역을 중심으로 구조를 바꾸고, 보호점수의 근거를 항목별로 보여주고, 사용자가 가중치를 직접 바꾸고, 법적 제외 조건과 자체 참고 감점을 구분하도록 개발했습니다.

## 개발을 통해 배운 것

- 데이터가 존재한다는 사실과 그 데이터가 믿을 만한 결론을 준다는 사실은 다릅니다.
- 출처 표시를 지켰다는 것만으로 모든 자료를 재배포할 수 있는 건 아닙니다.
- 자동 추천 결과보다는 판단 근거·자료 공백·미확인 항목을 함께 보여주는 것이 중요했습니다.
- AI 도구로 시제품을 빠르게 만들 수 있어도 설계, 오류를 발견하는 테스트, 데이터 의미 판단은 별도의 작업이었습니다.

## 지금 공개한 것과 남긴 것

실제 카카오 지도와 공간정보를 사용하는 로컬판은 v3.7.41.18까지 작업했습니다. 제3자 데이터가 포함된 통합 소스를 공개할 권한이 명확하지 않아, 이 저장소에는 완전 합성 데이터로 작동하는 별도 공개 데모를 두었습니다. 최신 로컬 기능 전체를 구현한 제품이라는 주장은 하지 않습니다.
