# GitHub 공개 배포 절차 — 파일뿐 아니라 과거 기록도 확인

## 순서

1. **이 ZIP만** 새 폴더에 풀고 내용물을 확인한다. `DO_NOT_UPLOAD` 및 `LOCAL_ONLY` ZIP을 절대 병합하지 않는다.
2. `npm test`를 실행한다. 저장소 안의 `docs/RELEASE_CHECKLIST.md`를 점검한다.
3. GitHub에 빈 새 저장소를 만들거나 기존 저장소의 **과거 커밋에 실제 자료가 전혀 없었다는 것을 확인**한 뒤 공개본만 반영한다. Git 커밋 이력에 한 번 공개된 파일은 현재 파일에서 삭제해도 기록에 남을 수 있다.
4. 기존 저장소에서 민감 자료 공개 이력이 의심되면 **기존 저장소에 무작정 덮어쓰지 않는다.** 먼저 Git 히스토리 및 공개 기록·포크/캐시·배포 상태를 점검하고 필요한 조치를 결정한다. 별도 새 저장소에 깨끗한 새 이력으로 공개하는 방법도 검토한다.
5. 공개되는 파일 목록을 다시 확인한다. GitHub에서는 `.gitignore`가 과거에 올라간 파일을 자동으로 삭제하지 않는다.
6. `Settings → Pages → Build and deployment → Deploy from a branch → main / (root)`를 선택한다.
7. 배포 URL에서 PC/휴대전화로 화면을 열어 점수·섹터·추천과 가상 데이터 안내를 확인한다.

## 이번 ZIP에서 의도적으로 제외한 자료

- 국토지리정보원/SGIS/서울시 실데이터, 원본·가공 GeoJSON, 실좌표, 사용자 저장 기록
- 실제 Kakao 지도 SDK, API 키, 관리자 인터뷰 원문, 지도 화면 캡처
- 로컬 `index.html` 자체: **이 파일의 내부에는 외부 JSON뿐 아니라 학교 경계가 HTML 내 JSON으로 직접 들어 있어** 외부 파일만 삭제해서는 공개 안전성을 확보할 수 없다.

## 라이선스 주의

원자료의 이용·변형 권한, 가공자료 재배포 권한, 국외 서버 사용 조건, 지도 SDK와 지도 타일 캡처 조건, 오픈소스 코드 라이선스는 각각 판단한다. 본 데모는 실제 데이터를 아예 포함하지 않는 방식으로 해당 데이터의 재배포 리스크를 회피한다. 다만 이것이 기존 GitHub의 전체 이력에 대한 법률상 안전 보증은 아니다.

소스코드에 전체 프로젝트용 라이선스를 자동으로 부여하지 않았다. 공개 라이선스 선택은 저장소 소유자가 별도로 결정한다.
